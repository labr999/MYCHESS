# 象棋開局譜 — 部署說明

這個資料夾可以直接上傳到任何 https 靜態託管服務。

## 檔案用途

| 檔案 | 用途 | 可否刪除 |
|---|---|---|
| `index.html` | 主程式（第 23 版） | 不可 |
| `coi-serviceworker.js` | 讓 GitHub Pages 等「無法自訂標頭」的平台也能啟用 Pikafish 引擎 | 若平台已設標頭可刪 |
| `_headers` | Netlify、Cloudflare Pages 的標頭設定 | 用其他平台可刪 |
| `vercel.json` | Vercel 的標頭設定 | 用其他平台可刪 |

`coi-serviceworker.js` 必須和 `index.html` 放在**同一層資料夾**才有效（瀏覽器規定 Service Worker 腳本必須同源）。

---

## 各平台部署方式

### GitHub Pages（適合長期保存、版本管理）

1. 建立一個新的 repository
2. 上傳 `index.html` 與 `coi-serviceworker.js`（`_headers`、`vercel.json` 用不到，可不上傳）
3. Settings → Pages → Source 選 `main` 分支 → Save
4. 幾分鐘後即可用 `https://<你的帳號>.github.io/<repo名>/` 開啟

GitHub Pages 不能自訂 HTTP 標頭，會由 `coi-serviceworker.js` 自動補上。**第一次開啟時頁面會自動重新整理一次**，這是正常的，之後即可啟用 Pikafish 引擎。

### Netlify（最快，可拖拉上傳）

拖拉整個資料夾到 https://app.netlify.com/drop 即可。`_headers` 會自動生效，Pikafish 引擎第一次就能直接啟用，不需重新整理。

> 未登入的部署可能過一段時間被清除，要長期保留請註冊免費帳號。

### Cloudflare Pages

上傳整個資料夾即可，同樣讀取 `_headers`。

### Vercel

上傳整個資料夾即可，讀取 `vercel.json`。

## 關於 Pikafish 引擎

分析面板的「🐟 啟用 Pikafish 引擎」需要瀏覽器的 **SharedArrayBuffer**，而這要求頁面具備跨來源隔離（COOP/COEP 標頭）。上面的設定就是為了這件事。

- **有設好標頭** → 點按鈕即可載入引擎（約 1.6MB，從 CDN 取得）
- **沒設好標頭** → 按鈕會顯示原因與解法，內建引擎與雲庫分析照常運作
- **以 `file://` 本機雙擊開啟** → 瀏覽器不允許 Service Worker，無法啟用 Pikafish；其餘功能不受影響

引擎啟用後，每步分析會顯示搜尋深度、最佳三著與中文主變化（PV），AI 教練也會改用引擎評分給回饋。

## 離線使用

`index.html` 本身是完整的單一檔案，不放到網路上、直接雙擊開啟也能用：棋譜瀏覽、記譜、匯入匯出、開局辨識、內建引擎分析全部正常，只有 Pikafish 引擎需要上述的 https 環境。

## 棋譜資料結構（第 26 版起）

棋譜已從 HTML 抽出，改放 `openings/` 資料夾，每個開局一個 JSON 檔：

```
openings/
  index.json              ← 檔案清單
  14-pingfengma.json      ← 中砲對屏風馬
  16-zuopaofengche.json   ← 左砲封車
  ...                     ← 共 33 個開局
```

每個開局檔的格式：

```json
{
  "side": "先手",
  "category": "中砲對屏風馬",
  "intro": "黑方雙馬並進形成屏風馬結構⋯⋯",
  "lines": [
    { "name": "專題清單（14部）", "playlistId": "PLxxxx" },
    { "name": "基本定式（30步）", "desc": "說明文字",
      "tokens": ["炮二平五", "馬8進7", "馬二進三"] }
  ]
}
```

著法用**中文記譜**存放，不是座標——好處是 Git diff 一眼看得懂改了哪一著，也不怕座標算錯。頁面載入時會用內建解析器重建座標並驗證合法性，記譜寫錯會在瀏覽器主控台指出是哪一檔哪一著。

**新增開局**：在 `openings/` 放一個新 JSON，然後把檔名加進 `index.json` 即可。`category` 不存在時會自動建立新分類。

### 兩種版本

| 版本 | 用途 | 開啟方式 |
|---|---|---|
| `index.html` + `openings/` | 部署到網站，Git 管理方便 | 需 http(s) |
| 單檔版 | 離線使用、隨身攜帶 | 雙擊即可 |

編輯完 `openings/` 的 JSON 後，可用 `tools/build_single.js` 重新產生離線單檔版（見 `tools/README.md`）。

## 大師棋庫（第 27 版新增）

按「🏆 大師棋庫」可依**棋手、賽事、年份**搜尋對局，點一下直接載入播放。多個關鍵字用空格分隔（例如「王天一 亞錦賽」會同時符合兩者）。

**本程式不內附任何大師對局資料**——棋譜有著作權與資料來源問題，需自行從合法來源取得。取得後放進 `openings/`，並在 `index.json` 加上檔名即可：

```json
{
  "masters": [
    {
      "red": "紅方棋手",
      "black": "黑方棋手",
      "event": "全國個人賽",
      "date": "2026-05-12",
      "result": "紅勝",
      "side": "先手",
      "category": "中砲對屏風馬",
      "tokens": ["炮二平五", "馬8進7", "馬二進三", "車9平8"]
    }
  ]
}
```

`openings/90-masters-template.json` 是可直接複製修改的範本（預設不載入，要用時把檔名加進 `index.json`）。

取得棋譜的實務做法：從 PlayOK 對局紀錄複製，或從東萍象棋網取得 DhtmlXQ 原始碼，用「📋 匯入棋譜」貼上後再用「📤 匯出棋譜」轉成中文記譜，填進上面的 `tokens`。

### 棋譜驗證

所有匯入的著法都會逐步驗證合法性。記譜寫錯時會明確指出是哪一著，例如：

> 「帥五進九」不是此局面的合法著法（可能是路數寫錯、該子被阻擋，或棋譜順序有誤）

第 27 版起移除了舊的寬鬆解析後援，壞資料不會再靜默混入棋庫。

## 程式架構（第 28 版重構）

### AppState — 狀態集中管理

原本散落的全域變數（`recording`、`currentMoves`、`_prevAnimIdx`、`analysisSeq`、`PF`⋯⋯共 20 個）已集中到單一物件：

```javascript
const AppState = {
  nav:      { cat, idx, moves, index, playTimer },   // 棋譜瀏覽
  rec:      { on, moves, selected, flip },           // 記譜模式
  render:   { theme, prevIdx, prevMode, lastCheckSpoken },
  analysis: { seq, lastRoot, curveCache },
  library:  { imported, masters },
  engine:   { ... },   // Pikafish WASM
  speech:   { ... }    // 語音合成
};
```

存取方式從 `recording` 變成 `AppState.rec.on`，從 `PF.state` 變成 `AppState.engine.state`。

### renderBoard — 拆分為單一職責函式

原本 134 行的單一函式拆成 9 個，總調度只剩 11 行：

```javascript
function renderBoard(){
  const ctx = getRenderContext();          // 取得局面上下文
  svg.innerHTML = renderDefs(ctx.theme)    // 主題漸層
                + renderGrid()             // 棋盤格線
                + renderAnnotations(ctx)   // 最後一步、選取框
                + renderPieces(ctx)        // 棋子
                + buildCaptureGhost(ctx);  // 吃子殘影
  triggerAnimations(ctx);                  // 走子滑移、殘影淡出、光圈
  updateStatus(ctx);                       // 將軍／絕殺
  updateAnalysis(ctx);                     // 開局辨識、曲線、引擎
}
```

棋子與吃子殘影共用 `pieceSvg()`，改棋子外觀只需改一處。

重構過程以 45 項行為測試（含 33 項 UI 互動）逐項比對，重構前後輸出完全一致。

## AI 教練評語分級（第 29 版）

記譜時每走一步，會依「與引擎首選的評分差距」給出分級與具體原因。

| 評級 | 條件 | 說明 |
|---|---|---|
| ✦ 妙手 | 引擎首選＋主動棄子 1.5 分以上 | 棄子取勢 |
| ★ 最佳 | 引擎首選 | — |
| ✔ 優秀 | 損失 < 0.20 分 | 與首選幾乎無差 |
| ○ 好棋 | 損失 < 0.50 分 | 穩健 |
| △ 不夠精確 | 損失 < 1.20 分 | 有更好的下法 |
| ✖ 失誤 | 損失 < 3.00 分 | 讓出明顯優勢 |
| ⚠ 漏著 | 損失 ≥ 3.00 分 | 局面可能就此逆轉 |

### 原因是算出來的，不是套話

評語裡的「原因」全部由引擎推導，只列可驗證的事實：

- **子力落空**：模擬走完後對方所有吃子著法，並計入我方回吃（靜態交換評估），只在「這一步新造成」淨損時才提示。原本就存在的威脅不會算在這步頭上。
- **錯過吃子**：首選是吃子而實走不是
- **放棄中路**：首選走向中路而實走沒有
- **形勢逆轉**：由領先轉為落後

實例：起始局面走「車九進一」會提示「走後對方可吃掉你的馬（淨損約 4.5 分）」——因為紅車離開底線後，[1,9] 的馬失去保護，黑方炮 2 進 7 可隔著紅炮直接吃掉。

### 本局正確率

每步的正確率由評分損失換算（0 分損失＝100%、1.2 分＝63%、3 分＝32%），並統計紅黑雙方本局平均，顯示於分析面板。開始新的記譜會自動重置。

## 第 33 版：修正記譜無法走子

第 32 版按下「先手記譜／後手記譜」後，點擊棋子只能選取、無法走子。原因是第 28 版把全域變數集中成 `AppState` 時，改名腳本漏掉並誤改了兩處：

1. **漏改**：`[...selectedPos]` 這種展開語法前面帶著 `...`，被「不匹配句點之後」的規則排除，走子時才會拋出 `selectedPos is not defined`
2. **誤改**：`classList.add('recording')` 裡的 CSS 類別名被當成變數改成 `'AppState.rec.on'`，導致記譜中的按鈕失去高亮樣式

原本的測試是直接寫入著法陣列來驗證記譜，繞過了滑鼠事件，所以沒抓到。已補上模擬實際點擊的測試（選子 → 走子 → 換方 → 翻轉視角），並納入常規測試套件。

## 第 35 版

### 修正：匯入的大師棋譜重新整理後消失

這是「按鈕沒有選項」的真正原因，而且是嚴重問題：儲存用的 `window.storage` 是 Claude 預覽環境專用 API，**部署到 GitHub Pages 後不存在**，任何匯入都存不住。已改為 `localStorage` 優先（一般瀏覽器）、`window.storage` 後援（預覽環境）。大師棋譜也補上了持久化（先前根本沒存）。現在匯入後重新整理，大師棋譜、一般匯入、記譜歷史全部都在。

### 大師棋譜進入首頁選單、分區顯示

分類下拉選單改為三區：

```
────── 📖 文字棋譜 ──────
────── 🎬 影音教學 ──────
────── 🏆 大師棋庫 ──────
```

同一分類若同時有棋譜和影片，會分別出現在對應區塊。點大師對局直接跳到棋譜播放。

### 記譜歷史

按「💾 儲存棋譜」時，除了自動分類，還會以時間戳存一份到「記譜歷史」分類（依記譜方歸屬先／後手，永久保存）。新按鈕「🕘 記譜歷史」一鍵叫出最近一筆。

自動分類與開局辨識的「深度吻合」門檻由 5 步提升為 10 步（棋譜不足 10 步時以全長為準）。辨識文字同步顯示「前 N 步完全吻合」。

## 第 37 版

### 開局辨識修正（歧義處理）

前幾步是許多開局的共同起手——「炮二平五 馬8進7 馬二進三 車9平8」同時是屏風馬、半途列砲等十餘條譜的開頭。先前只要全長吻合就採信第一條，短棋譜常被誤分類。

修正後的判定：吻合達 10 步才視為深度吻合；不足 10 步時，只有「全長吻合且僅一個分類達到最高分」才直接採信，**有歧義時交給開局特徵判斷**（黑方應手結構等），並誠實顯示「特徵判斷，約 70%」而非虛高的吻合百分比。

實測：4 步屏風馬開頭現在正確判為中砲對屏風馬（先前誤判半途列砲）；唯一吻合的飛象局仍直接採信；10 步以上顯示「前 N 步完全吻合，98%」。

### 大師對局依勝方歸檔

紅勝、和局 → 先手；黑勝 → 後手。研究後手開局時，看到的就是黑方獲勝的實戰。匯入訊息會註明「依勝方歸屬」。對局檔（openings/*.json）明示 side 時尊重原設定。

## 第 39 版：後手開局分類補齊

黑勝大師棋譜歸入後手區後，開局註記卻顯示先手分類名（如「中砲對順手砲」）——因為分類器缺少對應的後手規則。已補上四條：

| 黑方應法 | 分類 |
|---|---|
| 還中炮（砲8平5） | 後手順手砲 |
| 列手砲（砲2平5） | 後手列手砲 |
| 飛象固防 | 後手飛象應中砲 |
| 單提馬 | 後手單提馬 |

大師棋譜註記、開局辨識、後手記譜儲存三處同步生效。後手記譜存檔時若分類不存在會自動建立（例：儲存後手順手砲記譜 → 自動建立「後手順手砲」分類收納）。

### 東萍象棋網入口

## 第 41 版

### 合法著法提示

記譜模式選中棋子後，棋盤即時標示所有合法去處：空點畫綠色小圓點、可吃的子畫紅色虛線圈。走子或改選後自動清除。提示由完整規則引擎計算（蹩馬腿、塞象眼、炮架、九宮、河界、照面全部涵蓋）。

### 語音手動選擇

語音列新增語音下拉選單，列出裝置上所有可用語音（中文排前面），可手動指定並自動記住偏好，下次開啟沿用。預設仍為自動挑選（台灣國語優先）。切換時會念「已切換語音」供試聽。

### 關於影片轉譜與拍照識別

參考的棋者象棋是有伺服器後端的商業平台，影片轉譜與拍照識別都在其後端 AI 服務上運算。純前端單一 HTML 無法可靠實現這兩項（需要視覺模型與算力），故不提供陽春仿製版。現有替代路徑：教學影片可搭配文字棋譜雙軌收錄；紙本棋譜可用「📋 匯入棋譜」貼上文字。

## 第 42 版

### YouTube 影音匯入

「📋 匯入棋譜」現在也吃 YouTube 網址：貼上影片或播放清單連結（含 `list=` 自動識別為清單），即加入 🎬 影音教學區並永久保存。網址前加一行文字可自訂名稱；分類選單選「自動」時歸入「影音收藏」，也可手動指定既有分類。

### 東萍書籤工具修正

先前書籤在手機上常失敗，兩個原因：東萍是 http 站（部分安全 API 不可用）、完整棋譜碼常超過網址長度上限。改為雙軌：短棋譜照走網址自動匯入；長棋譜自動複製到剪貼簿後跳回本程式並開啟匯入面板，長按貼上一次即可。面板內補上手機建立書籤的具體步驟（Chrome 網址列輸入書籤名執行；iPhone Safari 書籤編輯替換網址）。
